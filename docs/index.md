# neomock — генератор моков для Go

**neomock** — инструмент генерации моков для Go-интерфейсов с собственным
zero-dependency рантаймом. Альтернатива mockery, minimock и gomock: типизированный
DSL настройки без строковых имён методов, без `any`-аргументов и без внешних
зависимостей в сгенерированном коде.

## Принципы дизайна

neomock построен вокруг четырёх идей:

1. **Типизированная настройка.** Имя метода не передаётся строкой, типы
   аргументов `When` берутся из сигнатуры интерфейса — опечатку в типе ловит
   компилятор.
2. **Собственный zero-dependency рантайм.** Сгенерированный мок импортирует
   только stdlib и пакет `neomock` — у потребителя не появляется новых
   зависимостей.
3. **Плоская конфигурация.** Один файл `.neomock.yml` (или директивы
   `go:generate`): источник каждого значения очевиден из одного места.
4. **Проверка вместо перезаписи.** Команда `check` отвечает на вопрос
   «свежие ли моки» без записи на диск — с unified diff и SARIF-выводом,
   удобно для CI.

## Ключевые решения

- **Один стиль настройки — `When/Then`, сложные случаи — `Run`.** Метод `EXPECT`
  не генерируется: аргументы `When` имеют конкретные типы, опечатка в типе —
  ошибка компиляции, а не тихий провал матча.
- **`neomock.Context` вместо `mock.Anything`.** Универсальный wildcard на `any`
  в DSL не используется: на практике «не матчить» нужно почти всегда только для
  контекста. Поэтому — один точечный wildcard, остальное матчится точно.
- **Zero-dependency рантайм.** Сгенерированный мок импортирует только stdlib и
  пакет `neomock`. Семантика сравнения совместима с `require.Equal`
  (~25 строк завендорены в рантайм), импорта testify нет.
- **Детерминированный вывод.** Повторный прогон без изменений не трогает файлы
  на диске (mtime сохранён — нет пересборки Go); `check` отличает свежий мок
  от устаревшего без ложных срабатываний.
