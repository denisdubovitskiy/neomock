# neomock

Генератор моков для Go — альтернатива mockery/minimock: типизированный DSL
`When/Then/Run`, zero-dependency рантайм. Публичная документация — `docs/`
(MkDocs), история изменений — `CHANGELOG.md`.

## Команды

```sh
go build ./... && go vet ./... && go test -race ./...   # полная проверка
go test -race ./internal/emitter                        # один пакет
NEOMOCK_UPDATE_GOLDEN=1 go test ./internal/emitter      # регенерация golden-моков
make lint                                               # golangci-lint в Docker (конфиг .golangci.yml)
make act                                                # CI локально через act (нужен Docker)
make docs-serve                                         # документация, dev-сервер
make docs-build                                         # документация, строгая сборка
```

`make docs-*` работает через локальное poetry-окружение (`pyproject.toml`,
`.venv` в корне); иных задач у Makefile нет.

## Границы (не менять руками)

- `internal/emitter/genmocks/*_mock.go` — сгенерированные моки-эталоны
  (dogfooding); правки только через регенерацию golden.
- Рантайм в корне модуля (пакет `neomock`) и весь сгенерированный код —
  zero-dependency: только stdlib + `neomock`. `testify` допустим только в
  тестах генератора (`internal/...`).
- `sandbox/` — локальные исследовательские копии mockery/minimock/gomock
  (отдельные go-модули, в git не попадают); не собирать, не рефакторить,
  не включать в изменения.

## Договорённости

- Вывод генератора обязан быть байт-детерминированным (skip-write-if-equal):
  методы сортируются по имени, импорты — по path; не добавляй обход map
  в порядок генерации.
- Сгенерированный мок никогда не держит мьютекс при вызове `Tester` или
  Run-функции (инвариант рантайма): снять копию под локом → отпустить →
  вызвать.
- Сообщения в сгенерированном коде — на английском в стиле expected/got.
- Длинные вызовы (>2 параметров или строка >80 символов) — каждый аргумент
  на отдельной строке; длинные строковые литералы и условия `if` не разбивать.
- Тесты генератора — на testify, с комментариями arrange/act/assert;
  race-детектор обязателен.

## Документация

Документация проекта — в `docs/` (MkDocs Material, конфиг `mkdocs.yml`,
сборка через poetry: `make docs-build` / `make docs-serve`). Карта страниц и
локальные конвенции — `docs/AGENTS.md`.

- Держи документацию в актуальном состоянии: любое изменение поведения кода,
  конфигурации, API или процессов сопровождай правкой соответствующих страниц
  в том же PR.
- Новые страницы добавляй в `nav` в `mkdocs.yml` ровно один раз.
- При перемещении или удалении страницы добавляй редирект (плагин `redirects`).
- Проверяй сборку перед мержем: `make docs-build` (или `make docs-serve`).

## После каждого изменения

Обязательно при завершении любой задачи:

1. **CHANGELOG.md** — добавь запись о изменении в формате Keep a Changelog
   (Unreleased или новая версия). Если файла нет — создай с нуля.
2. **README.md** — актуализируй после каждого изменения: новые возможности,
   изменённое поведение, команды. Если файла нет — создай.
3. **AGENTS.md** — актуализируй, если изменение затронуло команды, стиль,
   архитектуру или договорённости из этого файла.
